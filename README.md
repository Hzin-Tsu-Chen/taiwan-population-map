# 台灣餐飲業選址分析｜空間資料決策支援工具

> 🔗 **線上 Demo（支援手機）**：https://hzin-tsu-chen.github.io/taiwan-population-map/

整合兩個政府開放資料源，回答一個具體的商業決策問題：**「開一家餐飲店，全台哪個鄉鎮的市場最未飽和？」**

---

## 【使用技術】

- **Python / pandas** — 多來源資料整合、ETL
- **geopandas** — 空間資料處理、座標系轉換、幾何簡化
- **folium / Leaflet** — 互動式地圖視覺化
- **政府開放資料 API** — 內政部戶政司、衛福部食藥署
- **HTML / CSS / JavaScript** — RWD 響應式儀表板、跨框架事件通訊（postMessage）

## 【核心功能】

1. **多源資料整合**
   - 內政部戶政司（2025）：村里級人口，程式加總至 367 個鄉鎮
   - 衛福部食藥署：**22.8 萬筆**餐飲場所登錄資料，由地址解析至鄉鎮

2. **選址機會指數模型**
   ```
   機會指數 = 競爭分數 (60%) + 成長分數 (40%)

   競爭分數：每店服務人口的百分位（越高 = 店少人多 = 市場未飽和）
   成長分數：人口淨變化率的百分位（越高 = 需求成長中）
   評估門檻：僅納入人口 ≥ 20,000 的鄉鎮，確保市場規模
   ```

3. **互動式決策儀表板（RWD）**
   - 地圖分級著色：🟢 藍海（建議進場）／🔴 紅海（競爭激烈）
   - 點選鄉鎮即時顯示評估結果與建議
   - 藍海／紅海 Top 排名榜
   - 支援手機與桌機

## 【成果說明】

- **分析涵蓋**：367 個鄉鎮、2,328 萬人口、22.8 萬家餐飲場所
- **全國基準**：平均每家餐飲店服務 102 人
- **決策輸出**：辨識出市場未飽和的鄉鎮，例如臺中市外埔區（每店服務 376 人，為全國平均的 3.7 倍）

### 資料工程重點

- **地址解析除錯**：初版以正規表達式解析地址時，發現「前鎮區」被誤截為「前鎮」、「新市區」被誤截為「新市」（因鄉鎮名本身含「鎮/市」字元），導致部分行政區店數為 0。改以「已知鄉鎮名清單、最長名稱優先」比對後，解析成功率達 **99.96%**（僅 99 筆／22.8 萬筆無法對應）。
- **資料驗證**：以全國總人口（2,328 萬）、總店數等指標交叉驗證加總正確性。
- **行政區劃正規化**：處理圖資的桃園升格（桃園縣→桃園市）與官方用字（台→臺）。

### 模型限制（誠實揭露）

本模型以**居住人口**為市場基礎，但：
- **商業區被低估**：如臺中市中區有大量通勤消費人口，實際商機高於居住人口所反映。
- **郊區可能被高估**：外食習慣較低的區域，人口多不代表餐飲需求高。

實務選址仍需搭配人流、租金、交通可及性等資料。

## 如何執行

```bash
pip install geopandas folium pandas

python3 fetch_town_data.py   # 從政府 API 抓取資料 → town_indicators.csv
python3 site_analysis.py     # 分析並產生儀表板 → index.html
```

## 檔案說明

| 檔案 | 說明 |
|---|---|
| `fetch_town_data.py` | ETL：串接政府開放資料、地址解析、指標計算 |
| `site_analysis.py` | 選址模型、地圖與 RWD 儀表板產生 |
| `town_indicators.csv` | 367 個鄉鎮的整合指標 |
| `index.html` | 互動式選址儀表板（RWD）|
